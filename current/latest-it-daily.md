## ITEM 7: Optimizely Supply-Chain Attack — Malicious JavaScript Served to Visitors of 178 Organizations (Zoom, CNN, Fox News, BBC, Salesforce, GitLab, HSBC, Equifax); Card Skimmer, Wallet Swapper and iOS Exploit Kits

- WHAT / WHERE / WHEN: On 16 NOV an attacker exploited a vulnerability in the Optimizely Experimentation account signup flow and added malicious JavaScript to the "Project JavaScript" field of customer projects. The code was served from Optimizely's own CDN. Researcher Scott Helme (Report URI) found 188 infected files belonging to 178 organizations among 1,611 Optimizely scripts. Named sites include Zoom, the BBC, CNN, Fox News, Salesforce, GitLab, IKEA, HSBC, Equifax, Air France-KLM, Ledger, Peacock, Smartsheet, Stamps.com, Bitly, Mutual of Omaha, American Eagle and UNICEF USA. The injected loader pulled `hxxps://1688360[.]cc/track.js`, sometimes Base64-encoded, and some variants embedded the full payload in case the remote file was blocked. Payload capabilities: swapping crypto wallet addresses, skimming card data to `1688360[.]cc/card.php`, collecting cookies, URLs and screenshots, and loading the Coruna and DarkSword iOS exploit kits on iPhones and iPads. About $7,000 in crypto had reached attacker wallets by 16 NOV. Optimizely says it blocked the vulnerable path, deployed a fix, removed injected code, ended sessions, revoked tokens, reset affected accounts, blocked code delivery at Cloudflare and notified affected customers. Salesforce disabled Optimizely scripts across preview and production. Hudson Rock confirms links to exploit-kit infrastructure but says evidence "does not establish a zero-day, successful device exploitation." It also saw Kissmetrics, StorifyMe and Minute-ly scripts serving a loader to the same iOS infrastructure as early as 13 NOV (BleepingComputer, 2012 CST 16 NOV; Help Net Security, 0553 CST 17 NOV; SecurityWeek, 0422 CST 17 NOV).
- IMPACT ASSESSMENT: Anyone who bought something or used a crypto wallet on an affected site on 16 NOV may be exposed. Sites' own code was never touched, so tag-manager and third-party script governance is the control that matters. Out-of-date iPhones are the highest-risk endpoints.
- ACTION FOR ADMINS: Block `1688360[.]cc` at DNS and proxy, and hunt proxy logs for it since 13 NOV. If you run Optimizely Web, review Project JavaScript for unauthorized edits and rotate Optimizely credentials. Enforce CSP and Subresource Integrity where possible. Push iOS/iPadOS updates. For Kyle personally: check card statements for purchases made on listed sites on 16 NOV.
- SOURCE SYNOPSIS: BleepingComputer, Help Net Security and SecurityWeek (read directly); The Hacker News (headline); Report URI blog (via HN and quotes).
- FRAMING (TRADE/MAINSTREAM): Helme: "trusted JavaScript doesn't always remain trustworthy."
- FRAMING (COMMUNITY/ALT: HN, Reddit, X, forums): HN: "Optimizely compromised, served malware on Zoom, GitLab" (447 points, 191 comments). An X news summary (AI-generated) urges anyone who used affected sites that day to check transactions.
- CONFIDENCE: HIGH on the compromise and payload. LOW on any successful iOS exploitation (not established).

The evidence came from an exposed staging server running a multi-agent framework called exploit_agent, tied to several frontier and local LLMs. It turned new patches into exploits, and victim telemetry pointed to French media, entertainment and education sites. Other frameworks seen in intrusions: ARTEX, CAIRN, CyberStrikeAI, PentAGI and HexStrike AI. A suspected North Korean cluster, MIDNIGHT NEPTUNE, used AI-generated recruiter photos (SynthID-watermarked) and ClickFix lures, then edited `.claude/settings.json` in victims' repositories so launching Claude Code downloaded the SOMBERMEME backdoor. LLMJacking cases ran up fraudulent charges of more than $100,000 in a day, reaching $1 million in the worst cases (Help Net Security, 0245 CST 17 NOV). Barracuda: An attacker used a cloud access key Barracuda had given a third-party AI vendor and never retired ("That is on us"). The key was stolen in October from the vendor's GitHub configuration file. Over 44 hours on 1–2 NOV the attacker accessed about 10 cloud accounts, moving through analytics, source repositories and Kubernetes. The intrusion was discovered 4 NOV, and Barracuda attributes the "machine-speed intrusion" to the ARTEX framework. Commands targeted crypto keys and seed phrases, and an attempt to create a new cloud admin identity was blocked (BleepingComputer, 1357 CST 16 NOV). Luxor: Attackers compromised Luxor's Commander fleet-management software and redirected hashrate from just over a dozen client accounts to the OCEAN pool. Luxor patched within two hours, restored settings and promised reimbursement, and its CEO described it as AI-enabled (CoinDesk, The Block, search excerpts).
- IMPACT ASSESSMENT: Time-to-exploit after a patch is shrinking toward zero for web apps, and forgotten long-lived cloud keys are the common entry point. Developer-tool configuration files such as `.claude/settings.json` are now a persistence location.
- ACTION FOR ADMINS: Inventory and expire vendor and contractor cloud keys, and scan your vendors' public repositories for your secrets where contracts allow. Add `.claude/`, `.cursor/` and similar agent configuration files to code-review and EDR file-integrity monitoring. Set billing alerts and quotas on LLM API keys.
- SOURCE SYNOPSIS: Help Net Security on GTIG (read directly); BleepingComputer (read directly); SecurityWeek (headline); CoinDesk, The Block, Cointelegraph (search excerpts).

- FRAMING (COMMUNITY/ALT: HN, Reddit, X, forums): X news summaries (AI-generated) amplify the "fully autonomous AI hacker" framing and put the Luxor hijack at about 64,000 machines (unverified; see Quarantine).
