## ITEM 4: Cacti "4HTTP2SHELL" — Public PoC, Write-Up and Video Released Without Vendor Notice; RavenAI Calls It a Stored SQLi in Guest Graph Settings; Cacti Merges Develop-Branch Hardening of Guest Writes and User-Setting Validation (1924 CST 27 NOV) With a 1.2.31 Backport PR Still Open; No Release, No CVE, No Reported Exploitation

- WHAT / WHERE / WHEN: **BleepingComputer** (1106 CST 27 NOV): the exploit, renamed **"4HTTP2SHELL"** (previously 4HTTP2ROOT), was published on Thanksgiving by "ek0ms savi0r" in a GitHub repo called "Sad Girls 0day Club," with a technical write-up, PoC and video. In an Instagram post, the researcher said the bug was **not reported to Cacti** before release. It requires the **guest account enabled**; it was tested on **Cacti Core 1.2.31**, and it's unclear whether older versions are affected. **RavenAI** describes it as SQL stored in a guest user's graph display preferences, which later runs and rewrites the poller configuration to execute OS commands. **watchTowr** notes the resulting privileges depend on the account running the web server and poller, often not root. BleepingComputer: "As of November 27, there have been no reports of the vulnerability being exploited." **Upstream (GitHub, read directly):** PR **#9015**, "fix(security): [develop] harden user settings validation, Guest writes, and realtime graph access," was **merged 0124 UTC 28 NOV (1924 CST 27 NOV)**. It adds schema validation for user settings, returns HTTP 403 on Guest-account writes to profile and 2FA handlers, bounds numeric settings, and tightens realtime-graph authorization. It describes itself as a companion to a 1.2.x security PR. PR **#9017**, "fix(security): harden auth, realtime, links, graph source, automation, and settings on 1.2.31," is **open**. The latest release is still 1.2.31 (15 JUN 2026), and the newest published Cacti GHSA is from July. The PRs don't name 4HTTP2SHELL; the link is inferred from the code they touch.
- IMPACT ASSESSMENT: A public, weaponized PoC plus AI-assisted scanning makes exploitation of internet-exposed Cacti with guest enabled likely soon. Cacti holds SNMP and device credentials, so a compromised server is a pivot into the network. A fix exists in source but not in a release, so most admins can't patch yet. For Kyle's homelab and work monitoring: guest-off is the fix for now.
- ACTION FOR ADMINS: Disable the Cacti guest account. Restrict the web UI to management networks or a VPN. Review `poller_item` and data-input commands for unexpected entries, and check logs for non-numeric values in graph settings (`preview_graphs_per_page` etc.). Watch for a 1.2.32 or patch release and a CVE. Don't run the public PoC against production.
- SOURCE SYNOPSIS: BleepingComputer (read directly); Cacti GitHub PRs, releases and advisories via API (read directly). watchTowr and RavenAI as quoted by BleepingComputer. The researcher's repo was not read.

## ITEM 5: Web and Tooling Supply Chain — WebRTC Card Skimmer Found on Lascana, Samsonite, American Tourister, Revolve and FWRD Before Black Friday (Mobile Checkout Only, Exfiltration via Cloudflare TURN Relay, Outside CSP connect-src); All Removed 24–25 NOV; Convex Claude-Plugin Skills Sent Users' Project Ideas to a Remote Host and Told the Agent to Split Commands to Avoid Safety Classifiers

- WHAT / WHERE / WHEN: **Infohawk** (report dated 27 NOV; HN 553 points, 293 comments, posted 0940 CST 27 NOV) found a card skimmer on **Lascana** (through an altered **Quorum** marketing pixel), **Samsonite** and **American Tourister** (through an edited **Seers** cookie-banner setting), and **Revolve** and **FWRD** (through an altered file on Revolve's own CDN). The loader pulls `Insds.js` or `gtage.js` from Amazon S3 and runs only on small or touch screens (Samsonite: `/checkout` only). It fetches relay details (`GET /_cf/ice`, `POST /_cf/rel`) from a `northbridgeads[.]com` host, then receives the skimmer in chunks over a **WebRTC data channel via turn.cloudflare.com**, checks it against a SHA-256 digest and runs it with `eval`. Card data goes back the same way. Infohawk saw live exfiltration of its test card only at Lascana. The script grabs card details before payment authorization, so declined orders still leak data. Removal: Lascana/Quorum 24 NOV (Quorum restored a clean pixel 2109 UTC, 1509 CST), Samsonite and American Tourister 24 NOV 1425 UTC (0825 CST), Revolve confirmed 25 NOV. The number of victims is unknown. **Convex** (GitHub issue #64 on convex-backend-skill, opened 26 OCT, on HN 1202 CST 27 NOV, 331 points): three skills in a plugin listed in Anthropic's `claude-plugins-official` marketplace POSTed the user's one-sentence project idea to `basic-anteater-667.convex.site` (commented as telemetry), piped a script from that host into bash, and told the agent to split download and execute into separate calls because a combined command "is the shape harness safety classifiers block." The reporter said they read it as onboarding, not malice.
- IMPACT ASSESSMENT: Many US shoppers use these retailers, and Revolve, FWRD and Samsonite are US-facing. Any card entered on mobile at those checkouts in the week before Black Friday, until removal on 24–25 NOV, could be exposed. For site owners, the technique gets around the usual CSP-based Magecart defenses unless `connect-src` is strict. The Convex case shows AI-agent plugins can exfiltrate data and deliberately sidestep the safety tooling an admin turned on.
- ACTION FOR ADMINS: E-commerce teams: enforce a strict CSP `connect-src` allowlist, which blocks the two HTTP calls that set up WebRTC. Audit third-party pixels, consent-banner configs and CDN files for changes. Search for `northbridgeads`, `/_cf/ice`, `/_cf/rel`, `Insds.js`, `gtage.js` and unexpected `RTCPeerConnection` use on checkout pages, and test on mobile user agents. Consumers: watch statements, especially debit cards. Agent tooling: review plugin and skill sources before allowing them, and block outbound `curl | bash` from coding agents by policy.
- SOURCE SYNOPSIS: Infohawk report (read directly; single research source, vendor replies quoted). Convex GitHub issue (read directly). Neither Revolve, Quorum nor Convex statements were read independently.
- FRAMING (TRADE/MAINSTREAM): No mainstream trade coverage seen in the period. Infohawk: "the larger consumer web ecosystem should be prepared to mitigate these attack vectors."
- FRAMING (COMMUNITY/ALT: HN, Reddit, X, forums): HN treated the skimmer as the top security story of the day (553 points). HN commenters on Convex focused on the instruction to evade "harness safety classifiers."
- CONFIDENCE: MEDIUM-HIGH for the skimmer (detailed, reproducible indicators; single source). HIGH that the Convex issue text is as quoted.
