## ITEM 1: Microsoft — Reuters: "Code Red" After the 12 NOV Exchange Online Outage (One-Hour Resolution Target; Urgent Fix Took 5–6 Days to Saturate); Azure APIM Classic MZK9-GH0 Unchanged (Still No CVE, No Victim Count)

- WHAT / WHERE / WHEN: Per internal memos reviewed by Reuters (via Ars Technica 1636 CST 24 NOV and The Verge 0512 CST 25 NOV), **Microsoft 365 Core President Jason Henderson** called the 12 NOV outage the one with "the most customer impact in the history of Exchange Online" and declared a "Code Red." It brings daily meetings with the M365 engineering group, weekly reviews, and work on load shedding, geographic traffic partitioning and faster recovery. The target is **worldwide resolution within one hour** in future incidents, with AI agents to help diagnose. In a separate memo, Henderson wrote that an urgent production fix in a recent incident took **five to six days** to reach worldwide saturation, against a one-hour goal for the most urgent security fixes ("we aren't here yet"). CVP Amanda Silver described a "fog of war": responders traded messages across 11 Teams chats and a bridge call that hit the 1,000-participant limit (The Verge). Microsoft's 20 NOV post-incident report blamed an undetected Windows scalability defect introduced in July that caused lock contention in gateway processes. A Teams failover then added load while maintenance had about 14% of gateway capacity offline (Ars). **Azure APIM Classic (MZK9-GH0):** CSO Online (24 NOV) and others restate the known facts. Developer, Basic, Standard and Premium Classic tiers are affected; Consumption and v2 are not. Microsoft's fix does not invalidate stolen credentials. NSM's runtime-version check (0.52.x at 31936 or higher; 0.53.x at 31938 or higher) still stands. There is no CVE, no victim count and no public Microsoft advisory.
- IMPACT ASSESSMENT: The Code Red is a process change, not a fix. But Microsoft's own admission that urgent fixes can take days to saturate matters for anyone counting on Microsoft-side remediation, as with APIM and Entra Connect Health this month. For APIM, nothing changed: rotation is still on the customer.

APIM Classic (Developer/Basic/Standard/Premium): if you haven't rotated Named Values, IdP/OIDC client secrets, subscription keys and the back-end and Key Vault secrets they reference, do it before the long weekend, and check RuntimeVersion per NSM.

## ITEM 5: Windows and Microsoft 365 — November CVE-2026-118737 NTLM-Signing Fix Breaks Some Auth Proxies/SSO/Packaging Tools (Temporary Registry Workaround); SQL Server Linked-Server Connection Leak Still Open; M365 Apps "Blank Dialog" Fixed in Build 16.0.20625.20142; Grafana Ships Security Releases

- WHAT / WHERE / WHEN: **NTLM:** BleepingComputer (0302 CST 25 NOV) reports Microsoft has confirmed authentication failures after November updates that fix **CVE-2026-118737**, a Windows RPC runtime RCE. The fix is "the first phase of NTLM message-signing improvements." Affected: some third-party **authentication proxies, SSO solutions and application packaging tools** that set `NTLMSSP_NEGOTIATE_TARGET_INFO` but return an empty TargetInfo. Signs: an empty "Target Info List" in traces, or "Not Found" Target Machine values in event logs. No fix yet. Temporary workaround: set `ClientAllowUnsignedNtlm` (REG_DWORD) = 1 under `HKLM\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0`. Microsoft says the setting "may be removed in the future." Better: move to Kerberos or get a vendor update. Microsoft is also investigating printing failures with complex formatting. **SQL Server:** Windows release health (last updated 23 NOV) still lists linked-server OLE DB connections (Oracle, PostgreSQL) staying open after the October and later updates on Server 2012 through 2025. The mitigation requires contacting Microsoft Support for business. The SLMGR activation bug was fixed by the 13 NOV out-of-band updates (KB5136483/87/89/90/93). **M365 Apps:** a blank, undismissable dialog that blocked Outlook, Word, Excel, PowerPoint, OneNote and Access is fixed in **Version 2611 (Build 16.0.20625.20142)**. Stuck clients can force it with `officec2rclient.exe /update user updatetoversion=16.0.20625.20142` (BleepingComputer 0516 CST 25 NOV). **Grafana** released 12.4.16, 13.0.14, 13.1.11, 13.2.7 and 13.3.2 on 24 NOV (about 1147–1158 CST). The release notes list fixes for **CVE-2026-107561** and **CVE-2026-88960**; severity isn't published and neither is in NVD yet.

If it breaks, apply `ClientAllowUnsignedNtlm=1` only on affected clients and open a vendor ticket. Watch SQL linked-server connection counts and restart the service off-hours if needed. Push M365 Apps to 16.0.20625.20142. Upgrade Grafana to the 24 NOV patch line.

## ITEM 7: KEV — Three New Entries 24 NOV, All Due FRI 27 NOV: Drupal Core "Fail2Install" CVE-2026-132165 (Exploited Since 19 NOV), Idunno.AntiCsrf CVE-2026-131914 (EoL, No Patch), Optimizely Web Experimentation CVE-2026-132224 (Vendor-Side Fix; Forensic Triage); MailAssure and MONAI Label Due Tomorrow; Catalog 1,795

- WHAT / WHERE / WHEN: CISA's catalog **2026.11.24** (dateReleased 1747 UTC / **1147 CST 24 NOV**; 1,795 entries, up from 1,792) adds: **CVE-2026-132165, Drupal Core RCE**. An unauthenticated attacker can take over a site or run code by re-running `install.php`. Searchlight Cyber showed that exhausting resources (EMFILE, database connections, TCP source ports) makes Drupal think it isn't installed. The installer then writes an SQLite DB with a `.php` extension containing PHP payload, exploitable on Drupal 8.9, 9, 10 and 11 (THN). Drupal updated SA-CORE-2026-017 to say it was "exploited on live sites as early as 2026-11-19 19:00 UTC" (1300 CST 19 NOV). Drupal Steward WAF customers are covered for known vectors. The interim mitigation is to block `/core/install.php` (BleepingComputer 0410 CST 25 NOV). The flaw was found by Anthropic's OSS scanner. **CVE-2026-131914, Idunno AntiCsrf deserialization.** Unauthenticated RCE in the IIS worker via a crafted POST. The project is abandoned and no patch is expected. watchTowr sees probes "validating exploitation by triggering a web redirect." Mandiant advises replacing it with System.Web.Helpers.AntiForgery, ViewStateUserKey with MAC'd ViewState, or ASP.NET Core IAntiforgery (Help Net Security 0122 CST 25 NOV). **CVE-2026-132224, Optimizely Web Experimentation.** A signup-flow flaw let an attacker impersonate customer users and write Project JavaScript. Optimizely's report says malicious code was written from 0751 to 2224 UTC 16 NOV (0151–1624 CST) and was closed on Optimizely's side. Corgea and Report URI counted 188 snippets at 178 organizations, with a card skimmer, crypto clipper and iOS exploit-kit redirect. There is nothing to patch, but CISA requires forensic triage. All three are **due FRI 27 NOV** with BOD 26-04 forensic triage. **Due THU 26 NOV:** N-able MailAssure CVE-2026-134624 (fixed build 20261121.1943; Local Cloud operators must verify) and MONAI Label CVE-2026-133968 (fixed in **0.8.6**, released 21 NOV; authentication is off by default). **Past due 24 NOV:** Office CVE-2026-124194, Chromium CVE-2026-125350, BroadWorks CVE-2026-20320, Openwave CVE-2026-111793.

Idunno matters to anyone carrying legacy WebForms apps; there's no patch, only code changes. Optimizely is a retroactive forensics task for sites that ran the snippet on payment pages. A three-day window over Thanksgiving is unusually tight.
- ACTION FOR ADMINS: Drupal: upgrade per SA-CORE-2026-017 today. If you can't, deny `/core/install.php` at the web server and make `settings.php` non-writable, then hunt for new admin accounts and stray `.php` SQLite files under the docroot since 19 NOV. ASP.NET: grep for `Idunno.AntiCsrf` in bin and packages, replace it, or WAF-block anomalous POST bodies meanwhile. Optimizely Web customers: review CSP reports, outbound requests to `1688360[.]cc`, and card and crypto transactions for 16 NOV. MailAssure Local Cloud: confirm build 20261121.1943 or later. MONAI Label: 0.8.6, auth on, off untrusted networks.
- SOURCE SYNOPSIS: CISA KEV JSON (diffed against the 23 NOV copy) and the 24 NOV CISA alert (read). BleepingComputer, THN and Help Net Security (read). Optimizely, Corgea, N-able, SecurityWeek and the MONAI Label 0.8.6 release via search excerpts.
